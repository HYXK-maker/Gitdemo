一、项目概述  

1. 项目背景

本项目源于小型团队（课程小组、班级、社团）文档管理的实际需求，当前小型团队普遍存在文档分散存储、版本混乱、协作低效、权限管控缺失等问题，导致团队成员查阅、编辑、共享文档不便，影响协作效率。基于此，开发一套轻量级团队协同文档知识库系统，实现文档集中管理、在线编辑、版本追溯与权限管控，解决上述痛点，同时贴合课程实践要求，将理论知识与实际开发相结合，提升团队开发能力。

2. 系统目标

本系统旨在开发一套轻量级、易操作、高适配的团队协同文档知识库系统，核心目标如下：

- 实现用户注册登录、身份验证与角色区分，保障系统访问安全；

- 实现多级目录管理与文档增删改查，支持文档集中存储与分类管理；

- 实现富文本在线编辑与自动保存，支持文档历史版本追溯与回滚；

- 实现细粒度权限管控，区分不同用户对目录、文档的查看、编辑权限；

- 搭建简洁直观的用户界面，适配学生用户使用习惯，降低操作成本；

- 完成前后端协同开发与系统测试，确保系统稳定、流畅运行，满足课程设计实践考核要求。

3. 开发环境

- 开发工具：前端（VS Code）、后端（IntelliJ IDEA）、数据库管理（Navicat Premium）、版本控制（Git）；

- 运行环境：操作系统（Windows 11、WSL、macOS）、JDK 1.8+、浏览器（Chrome/Edge 版本≥80）、Node.js（前端运行依赖）；

- 数据库：MySQL 5.7/8.0（字符集utf8mb4）。

三、系统设计  

1. 系统架构

本系统采用前后端分离架构设计，整体划分为前端展示层、后端业务逻辑层、数据持久层三层结构，层次清晰、耦合度低，便于分组开发与后期维护，系统架构图如下 ：

![系统架构图](./assets/xtjg.png)

各层级职责说明：

- 前端展示层：面向用户实现全部页面与交互，包含登录注册、目录树导航、文档编辑、版本查看、权限配置等界面；通过浏览器发起网络请求，接收后端接口数据并完成页面渲染与用户交互。

- 后端业务层：提供统一接口服务，负责接收前端请求，完成用户认证、权限校验、目录管理、文档操作、版本管理等核心业务逻辑处理，实现数据的加工与转发（当前由第三位成员开发中）。

- 数据持久层：基于MySQL数据库，使用标准SQL语句完成数据的增、删、改、查操作，持久化存储用户信息、目录数据、文档内容、历史版本及权限配置等数据，保障数据长期稳定保存。

2. 模块设计

系统按功能划分为五大核心模块，各模块职责明确、协同工作，具体如下：

- 用户模块：负责用户注册、登录、身份验证、角色管理，区分管理员与普通用户，管控用户访问权限，支撑整个系统的安全访问。

- 目录管理模块：负责多级目录的创建、删除、重命名、移动，维护目录上下级层级关系，实现文档的分类收纳与管理。

- 文档管理模块：负责文档的新建、保存、编辑、删除、搜索，集成富文本编辑器，实现文档内容的在线编辑与自动保存，支撑核心业务场景。

- 版本管理模块：负责记录文档每次修改后的历史版本，实现版本查询、版本回溯功能，确保文档编辑过程可追溯、误操作可恢复。

- 权限管理模块：负责用户与目录、文档的权限绑定，区分查看、编辑、管理三种权限等级，实现细粒度权限管控，防止越权操作。

各模块关联关系：用户模块为其他所有模块提供身份校验与权限支撑；目录管理模块为文档管理模块提供分类存储载体；文档管理模块与版本管理模块联动，实现文档内容与版本的同步管理；权限管理模块贯穿所有模块，管控用户对各模块的操作权限。

围绕系统业务逻辑，设计5张核心数据表，均采用InnoDB存储引擎，支持事务处理与外键关联，使用标准SQL语句创建，具体设计如下：

1. 用户表（user）

CREATE TABLE user (
    id INT PRIMARY KEY AUTO_INCREMENT COMMENT '用户ID（主键）',
    username VARCHAR(50) NOT NULL UNIQUE COMMENT '登录账号，唯一',
    password VARCHAR(100) NOT NULL COMMENT '加密存储的登录密码',
    nickname VARCHAR(50) DEFAULT '普通用户' COMMENT '用户昵称',
    contact VARCHAR(20) DEFAULT '' COMMENT '联系方式',
    role VARCHAR(20) DEFAULT 'user' COMMENT '用户角色，admin-管理员，user-普通用户',
    status TINYINT DEFAULT 1 COMMENT '账号状态，1-正常，0-禁用',
    create_time DATETIME DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
    update_time DATETIME DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间'
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='用户信息表';

2. 文档目录表（directory）

CREATE TABLE directory (
    id INT PRIMARY KEY AUTO_INCREMENT COMMENT '目录ID（主键）',
    name VARCHAR(100) NOT NULL COMMENT '目录名称',
    parent_id INT DEFAULT 0 COMMENT '父目录ID，0表示根目录',
    user_id INT NOT NULL COMMENT '创建人ID，关联user表',
    sort INT DEFAULT 0 COMMENT '排序权重，用于调整目录显示顺序',
    path VARCHAR(255) DEFAULT '' COMMENT '目录路径，用于层级遍历',
    level INT DEFAULT 1 COMMENT '目录层级，根目录为1',
    is_delete TINYINT DEFAULT 0 COMMENT '删除状态，0-未删除，1-已删除',
    create_time DATETIME DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
    update_time DATETIME DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
    FOREIGN KEY (user_id) REFERENCES user(id) COMMENT '关联用户表，创建人'
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='文档目录表';

3. 文档主表（document）

CREATE TABLE document (
    id INT PRIMARY KEY AUTO_INCREMENT COMMENT '文档ID（主键）',
    title VARCHAR(200) NOT NULL COMMENT '文档标题',
    content TEXT COMMENT '文档内容',
    dir_id INT NOT NULL COMMENT '所属目录ID，关联directory表',
    user_id INT NOT NULL COMMENT '创建人ID，关联user表',
    last_edit_user INT COMMENT '最后编辑人ID，关联user表',
    doc_type VARCHAR(20) DEFAULT 'rich_text' COMMENT '文档类型，rich_text-富文本，markdown-Markdown，table-表格',
    status TINYINT DEFAULT 1 COMMENT '文档状态，1-正常，0-禁用',
    is_delete TINYINT DEFAULT 0 COMMENT '删除状态，0-未删除，1-已删除',
    create_time DATETIME DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
    update_time DATETIME DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
    FOREIGN KEY (dir_id) REFERENCES directory(id) COMMENT '关联目录表',
    FOREIGN KEY (user_id) REFERENCES user(id) COMMENT '关联创建人',
    FOREIGN KEY (last_edit_user) REFERENCES user(id) COMMENT '关联最后编辑人'
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='文档主表';

4. 文档版本表（document_version）

CREATE TABLE document_version (
    id INT PRIMARY KEY AUTO_INCREMENT COMMENT '版本ID（主键）',
    doc_id INT NOT NULL COMMENT '关联文档ID，关联document表',
    content TEXT COMMENT '该版本的文档内容',
    version_num INT NOT NULL COMMENT '版本号，自增',
    user_id INT NOT NULL COMMENT '操作人ID，关联user表',
    change_desc VARCHAR(255) DEFAULT '' COMMENT '变更说明',
    create_time DATETIME DEFAULT CURRENT_TIMESTAMP COMMENT '版本生成时间',
    FOREIGN KEY (doc_id) REFERENCES document(id) COMMENT '关联文档表',
    FOREIGN KEY (user_id) REFERENCES user(id) COMMENT '关联操作人',
    UNIQUE KEY (doc_id, version_num) COMMENT '文档ID+版本号唯一，避免重复版本'
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='文档版本表';

5. 文档权限表（permission）

CREATE TABLE permission (
    id INT PRIMARY KEY AUTO_INCREMENT COMMENT '权限ID（主键）',
    user_id INT NOT NULL COMMENT '用户ID，关联user表',
    target_id INT NOT NULL COMMENT '资源ID，关联directory或document表',
    target_type VARCHAR(20) NOT NULL COMMENT '资源类型，directory-目录，document-文档',
    perm_type VARCHAR(20) NOT NULL COMMENT '权限类型，view-查看，edit-编辑，manage-管理',
    expire_time DATETIME DEFAULT NULL COMMENT '权限过期时间，NULL表示永久有效',
    create_time DATETIME DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
    FOREIGN KEY (user_id) REFERENCES user(id) COMMENT '关联用户表',
    UNIQUE KEY (user_id, target_id, target_type) COMMENT '用户+资源+资源类型唯一，避免重复授权'
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='文档权限表';

1. 关键技术

本系统采用主流、轻量、易上手的技术栈，贴合课程设计要求，核心关键技术如下：

- Tiptap：富文本编辑器组件，实现文本格式化、列表、引用、代码块等编辑功能，支持防抖自动保存；

- Pinia：状态管理工具，统一管理用户token、登录状态等全局数据，实现组件间数据共享；

- Axios：请求工具，封装后实现请求拦截、响应拦截，统一处理接口请求与错误，自动携带token；

- Vue Router：路由管理工具，实现页面跳转与未登录拦截，管控页面访问权限。

（2）数据库关键技术

- MySQL：关系型数据库，支持标准SQL语句，实现数据持久化存储，适配小型团队数据管理需求；

- 索引优化：为目录表、文档表的核心字段（parent_id、dir_id、user_id）添加索引，提升查询效率；

- 外键约束：通过外键关联各数据表，保障数据一致性与关联性，实现数据溯源；

- 字符集配置：设置utf8mb4字符集，解决特殊符号、表情存储乱码问题；

- 容错设计：SQL脚本添加if not exists判断，避免重复创建数据库、数据表，适配多环境部署。

 (3) 后端相关技术

- 核心框架：Spring Boot	3.x 系列。

- 安全框架：Spring Security + JJWT	推荐 Spring Security 6.x。

- 数据库驱动：MySQL Connector/J	版本与 MySQL 服务器版本。

- 持久层框架：MyBatis-Plus 3.5.x 系列。


（4）技术难点解决方案

- 跨域问题：通过Vite代理配置，将前端/api请求代理至后端8080端口，解决前后端跨域交互问题；

- 文档内容乱码：将数据库字符集设置为utf8mb4，调整后端接口编码处理逻辑，确保富文本内容正常存储；

- 接口格式不统一：提前约定JSON数据格式，编写接口文档，同步确认参数定义，避免联调报错。

（1）前端路由守卫代码

// src/router/index.js
import { createRouter, createWebHistory } from 'vue-router'
import { useUserStore } from '@/stores/user'
import Login from '@/views/Login.vue'
import Register from '@/views/Register.vue'
import Main from '@/views/Main.vue'

const routes = [
  { path: '/', redirect: '/login' },
  { path: '/login', component: Login, name: 'Login' },
  { path: '/register', component: Register, name: 'Register' },
  { 
    path: '/main', 
    component: Main, 
    name: 'Main',
    meta: { requireAuth: true } // 需要登录才能访问
  }
]

const router = createRouter({
  history: createWebHistory(),
  routes
})

// 路由守卫：未登录拦截
router.beforeEach((to, from, next) => {
  const userStore = useUserStore()
  // 判断当前页面是否需要登录
  if (to.meta.requireAuth) {
    // 已登录则放行，未登录则跳转至登录页
    if (userStore.token) {
      next()
    } else {
      next('/login')
    }
  } else {
    next()
  }
})

export default router

（2）Axios封装代码

// src/api/request.js
import axios from 'axios'
import { useUserStore } from '@/stores/user'

// 创建Axios实例
const request = axios.create({
  baseURL: import.meta.env.VITE_API_BASE_URL, // 统一基础路径
  timeout: 5000 // 超时时间
})

// 请求拦截器：自动携带token
request.interceptors.request.use(
  (config) => {
    const userStore = useUserStore()
    if (userStore.token) {
      config.headers.Authorization = `Bearer ${userStore.token}`
    }
    return config
  },
  (error) => {
    return Promise.reject(error)
  }
)

// 响应拦截器：统一错误处理、401未授权退出
request.interceptors.response.use(
  (response) => {
    // 成功响应，直接返回数据
    return response.data
  },
  (error) => {
    const userStore = useUserStore()
    // 401未授权，清除token并跳转至登录页
    if (error.response?.status === 401) {
      userStore.logout() // 清除token和用户信息
      window.location.href = '/login'
    }
    // 其他错误提示
    ElMessage.error(error.response?.data?.msg || '操作失败，请稍后再试')
    return Promise.reject(error)
  }
)

export default request

改进方向：后期优化界面样式，完善交互逻辑，提升用户操作体验。

不足3：测试工作尚未全面开展，未发现潜在BUG。

改进方向：按照测试方案，逐步开展单元测试、集成测试，提前排查问题，确保系统稳定。

2.2 结项阶段最终不足与改进方向
不足1：全文搜索功能未实现

表现：前端搜索框仅支持前端过滤，未实现后端关键词搜索文档/目录内容。

改进方向：后续可引入Elasticsearch或MySQL全文索引，实现高效的文档内容检索。

不足2：回收站功能已开发但暂时隐藏

表现：回收站功能代码已完成，但因团队分工协调问题暂时隐藏入口。

改进方向：后续版本可重新启用回收站，实现文档/目录的软删除和恢复。

不足3：数据库初始化脚本未包含旧字段兼容

表现：initial.sql与当前代码结构不完全匹配，需手动调整部分字段默认值。

改进方向：已修正SQL脚本并推送至GitHub，后续维护中需保持脚本与代码同步更新。

不足4：权限管理粒度较粗

表现：当前权限管控仅支持用户级数据隔离和角色管理，不支持文档/目录级别的细粒度权限设置（如指定某文档对某用户可见/可编辑）。

改进方向：后续可引入RBAC权限模型，实现文档级和目录级的独立权限控制。

不足5：缺少自动化测试

表现：当前测试均为手动功能测试，未编写自动化单元测试和集成测试代码。

改进方向：后续可引入JUnit和Selenium等工具，建立自动化测试体系。

不足6：性能优化空间

表现：当前系统未进行压力测试和性能调优，高并发场景下的性能表现未知。

改进方向：后续可增加缓存机制（Redis）、数据库连接池优化、前端代码分割等。

数据库表结构
系统共包含4张核心数据表：

表名	说明	关键字段
user	用户表	id, username, password, role, status
directory	目录表	id, name, type, parent_id, user_id
document	文档表	id, title, content, directory_id, user_id
document_version	版本表	id, doc_id, content, version_num, version_note
系统架构说明
前端：Vue 3 + Vite + Element Plus + Pinia + Vue Router

后端：Spring Boot双服务架构（8080核心业务 + 8081请求转发）

数据库：MySQL 8.0，通过MyBatis进行ORM映射

数据隔离：基于user_id的用户级数据隔离

权限控制：基于role字段的角色权限管理（admin/user）

开发环境说明
本项目使用WSL 2（Windows Subsystem for Linux）作为开发环境，Ubuntu 22.04子系统，确保了Linux开发体验与Windows桌面环境的兼容。

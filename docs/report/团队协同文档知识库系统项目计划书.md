## 一、项目概述

### 1. 项目背景
​	在日常学习、课程项目协作及小型团队活动中，文档资料的管理存在诸多痛点：文档分散存储于个人设备、社交平台等不同渠道，查找不便；多人协作编辑时，版本混乱、修改痕迹难以追溯，易出现内容冲突、误删等问题；现有大型协同文档工具（如 Notion、语雀）功能繁杂、学习成本高，且部分功能超出学生团队的实际需求，不适用于课程项目场景。
​	本项目源于课程设计要求，结合小型团队（如课程小组、班级、社团）的文档管理需求，开发一套轻量级协同文档知识库系统。其应用场景主要覆盖学生团队课程报告撰写、项目资料归档、共享笔记整理等，可实现文档的集中管理、在线编辑、版本留存与权限管控。
​	该项目的现实意义在于，解决小型团队文档管理混乱、协作低效的问题，为学生团队提供简单易用、低成本的协同文档工具；同时，通过项目开发，将前后端开发、数据库设计、文档撰写等知识应用于实践，提升团队成员的技术能力与协作能力，贴合课程设计的实践目标。

### 2. 项目目标
​	本项目旨在开发一套轻量级团队协同文档知识库系统，以解决小型团队文档管理混乱、协作低效的痛点，结合课程设计要求，拟实现以下主要目标：
1.  完成核心功能开发，实现10项既定功能（用户登录注册、目录管理、文档增删改查、版本管理、权限控制等），确保系统基础功能稳定可用。
2.  搭建简洁直观的用户界面，操作逻辑清晰，适配学生用户使用习惯，降低学习与操作成本，无需复杂培训即可上手。
3.  实现文档集中管理、在线富文本编辑、历史版本追溯与权限管控，满足小型团队（课程小组、班级）的文档协作需求。
4.  完成前后端协同开发、数据库设计与系统测试，确保数据存储安全、操作流畅，无明显功能bug。
5.  同步完成项目全流程文档撰写与汇报准备，实现理论知识与实践开发的结合，达成课程设计的实践考核目标。
### 3. 开发环境与条件

​	本项目采用前后端分离的开发模式，使用主流、轻量、易上手的开发工具与环境，满足课程设计开发需求，具体如下：
1. **开发工具**
- 前端开发工具：VS Code
- 后端开发工具：IntelliJ IDEA / Eclipse
- 版本控制工具：Git

2. **技术框架**
- 前端：Vue.js + Element UI
- 后端：SpringBoot（Java）
- 富文本编辑器：开源在线编辑器组件

3. **数据库**
- 数据库管理系统：MySQL
- 数据库可视化工具：Navicat

4. **运行环境**
- 服务器端：JDK 1.8+
- 浏览器端：Chrome / Edge 等现代浏览器
- 操作系统：Windows 10/11

## 二、需求分析

### 1. 目标用户与使用场景
- 目标用户

  本系统主要面向学生小组、班级、小型社团及小型协作团队，主要包含三类使用对象：

  1. 系统管理员：负责整体用户管理、基础目录维护与系统权限统筹；

  2. 普通创建用户：可自主创建目录、编写文档、管理个人资料并配置文档权限；
  3. 浏览协作用户：依托开放权限，查看共享文档、查阅资料，参与轻量化协作。

- 使用场景
  1. 课程小组协作：团队统一存放项目文档、实验报告、开发资料，集中管理文件；
  2. 班级资料归档：统一收纳课件、作业、通知文件，方便全体成员查阅；
  3. 个人知识整理：个人建立知识库，分类记录笔记、学习资料与总结文档；
  4. 小型团队协作编辑：多人依托权限控制，分工编辑、查阅文档，避免文件版本混乱。

### 3. 非功能需求

- 性能方面

1. 响应性能：所有核心操作（打开文档、切换目录、保存内容、调取历史版本）响应时间≤1秒，无明显卡顿；
2. 加载性能：单篇文档加载时间≤3秒，历史版本调取时间≤2秒，目录树展开/折叠无延迟，SQL查询效率稳定；
3. 稳定性：系统连续运行72小时无崩溃、无闪退，MySQL数据库数据实时同步，无数据丢失、错乱；
4. 并发性能：支持同时50人在线操作，文档编辑、权限设置等操作无卡顿，SQL事务处理无异常；
5. 数据处理：支持存储1000+文档及历史版本，SQL查询、插入、修改操作高效，无明显延迟。

- 安全方面

1. 数据安全：MySQL数据库采用加密存储，用户密码、文档内容均进行加密处理；定期自动备份数据库，防止误操作、系统故障导致的数据丢失，支持SQL备份与恢复；
2. 操作安全：删除、修改文档/目录、权限变更等关键操作需二次确认，避免误操作；操作日志留存，可追溯关键操作记录（通过SQL查询操作日志）；
3. 权限安全：严格通过SQL查询校验用户权限，区分管理员、普通用户、访客角色，禁止越权操作（如普通用户无法修改管理员文档、无法执行SQL删除/修改核心数据表操作）；
4. 隐私安全：用户账号、密码加密存储，不泄露个人信息及文档内容；禁止非法访问MySQL数据库，防止数据泄露。

- 兼容性

  1. 浏览器兼容：支持Chrome、Edge、Firefox等主流浏览器（版本≥80），界面无格式错乱，文档编辑、SQL驱动加载正常； 

  2. 设备与系统兼容：适配Windows 10/11、macOS系统，电脑、平板终端均可正常打开操作，MySQL数据库在不同系统下运行稳定；
  3. 技术兼容性：前端Vue框架与后端SpringBoot框架适配良好，SQL语句兼容MySQL 5.7/8.0版本，无语法冲突；
  4. 格式兼容：文档可正常导出为常用格式（TXT、PDF），与课程要求的计划书、汇报材料格式适配；MySQL数据库导出的数据可正常查看、复用。

- 易用性
  1. 界面简洁直观，操作逻辑清晰，适配学生用户使用习惯，无需复杂培训即可上手；
  2. 文档编辑操作便捷，富文本编辑功能简单易用，SQL后台数据交互无感知，不影响用户操作；
  3. 错误提示清晰，如权限不足、操作失败等场景，给出明确提示，引导用户正确操作。

## 三、技术路线

### 1. 总体架构
​	本系统采用前后端分离架构设计，整体划分为前端展示层、后端业务逻辑层、数据持久层三层结构，层次清晰、耦合度低，便于分组开发与后期维护。

1. 前端展示层

   ​	面向用户实现全部页面与交互，包含登录注册、目录树导航、文档编辑、版本查看、权限配置等界面；通过浏览器发起网络请求，接收后端接口数据并完成页面渲染与用户交互。

2. 后端业务层

   ​	提供统一接口服务，负责接收前端请求，完成用户认证、权限校验、目录管理、文档操作、版本管理等核心业务逻辑处理，实现数据的加工与转发。

3. 数据持久层

   ​	基于MySQL 数据库，使用标准SQL 语句完成数据的增、删、改、查操作，持久化存储用户信息、目录数据、文档内容、历史版本及权限配置等数据，保障数据长期稳定保存。前后端通过接口进行数据交互，各层级职责明确，能够适配小组多人分工并行开发，满足本次课程设计项目开发需求。

### 2.主要技术

#### 一、 前端技术方案

- **技术选型：** 采用 Vue3 + Element UI框架，搭建响应式前端页面，确保多端适配与流畅交互。
- **核心技术：**
  - **页面布局：** 基于 HTML5 + CSS3构建目录树与文档编辑界面，保证界面简洁直观。
  - **富文本编辑：** 集成开源富文本组件，支持文本格式化与内容实时保存，降低开发复杂度。
  - **浏览器兼容：** 适配 Chrome、Edge 等主流浏览器，采用响应式布局防止格式错乱。
- **核心操作：** 实现页面跳转、按钮交互及表单提交，通过接口与后端联动，确保数据实时同步。

#### 二、 后端技术方案

- **技术选型：** 采用 Java SpringBoot 框架，负责核心业务逻辑、接口开发及权限校验。
- **核心技术：**
  - **接口开发：** 遵循 RESTful*风格，编写用户、文档、权限相关接口，支持高效的数据增删改查。
  - **权限控制：** 动态校验用户角色，实现精细化的访问控制，从后端杜绝越权操作。
  - **数据交互：** 建立稳定的数据传输通道，确保前端操作与数据库状态高度一致。

#### 三、 数据库技术方案

- **数据库选型：** MySQL（关系型数据库），凭借其稳定性和易维护性，满足课程设计的数据存储需求。
- **核心技术：**
  - **数据存储：** 通过 SQL 语句实现用户信息、文档内容及权限配置的持久化存储。
  - **数据安全：** 利用事务处理与 SQL 备份机制，确保文档版本管理与历史数据的安全性。
  - **标准适配：** 采用标准 SQL 语法，确保与前后端逻辑完美匹配。

#### 四、 关键技术说明

1. **前后端交互：** 统一通过 HTTP 接口进行数据传递，实现“前端请求-后端处理-数据返回”的闭环，保证操作流畅。
2. **富文本集成：** 直接集成成熟的开源组件，避免重复造轮子，提升开发效率。
3. **多重数据校验：** 结合后端逻辑与 SQL 约束，实现权限校验与操作二次确认，防止误删或非法修改。
4. **轻量级版本管理：** 通过数据库记录版本流水，以较低的开发成本实现高效的历史版本追溯。

### 3.数据设计初步考虑

#### 一、 主要实体或对象

结合协同文档管理业务，系统抽取的五个核心实体对象如下：

- **用户实体：** 记录系统使用者信息（含管理员与普通用户），用于登录认证、身份区分和权限绑定。
- **目录实体：** 以多级文件夹形式存在，用于分类收纳文档，维护上下级目录的层级关系。
- **文档实体：** 系统核心业务对象，包含文档标题、正文内容、所属目录、创建人等基础信息。
- **文档版本实体：** 记录文档每次修改后的历史内容、版本编号与修改时间，用于版本查询与回溯。
- **权限实体：** 绑定用户与对应的目录或文档，区分只读、编辑等操作权限，实现资源访问控制。



#### 二、 关键数据表及数据关系

系统采用 **MySQL** 数据库，通过以下五张核心数据表实现数据的持久化与关联：

| **数据表名**         | **对应实体** | **说明**                                                     |
| -------------------- | ------------ | ------------------------------------------------------------ |
| **user**             | 用户表       | 存储注册用户基础信息，是权限与资源归属的核心关联主体。       |
| **directory**        | 目录表       | 记录名称、父目录 ID 及创建者；通过自关联实现多级树状结构，与用户为多对一关系。 |
| **document**         | 文档表       | 存储标题、正文、所属目录及创建人；与目录为多对一关系（一个目录下可有多个文档）。 |
| **document_version** | 文档版本表   | 存储历史修改记录；通过文档 ID 与文档表形成一对多关联，记录多个历史镜像。 |
| **permission**       | 权限表       | 关联中间表，建立用户与资源（目录/文档）的映射，通过权限字段控制操作范围。 |

------



#### 三、 整体数据关系总结

系统的数据架构逻辑清晰，依赖关系简单，便于使用 SQL 语句进行高效维护：

1. **用户中心化：** 用户统一管理其名下的目录与文档。
2. **层级分类：** 目录承载文档分类，支持无限级嵌套。
3. **追踪溯源：** 文档关联多条版本记录，支持随时回滚。
4. **灵活授权：** 权限表独立解耦，可精细化绑定用户与特定资源的访问关系。

这种设计能够有效满足业务数据的持久化需求，并为后续的功能扩展预留了空间。

### 2. Git 协作方式

本项目采用 **Git** 进行版本控制，确保团队开发的高效性与代码安全性：

1. **仓库管理：** 建立远程托管仓库，作为唯一的代码与文档事实来源，成员定期执行 `pull/push` 保证版本同步。
2. **分支管理策略：**
   - `main` 分支：长期维护的稳定分支，仅存放最终发布的正式版本。
   - `dev`分支：开发主分支，用于整合各模块成果并进行集成测试。
   - `feature/` 分支：功能分支（如 `feature/login`），成员在各自独立的分支开发，严禁直接修改 `main`。
3. **提交与合并流程：**
   - **开发：** 在功能分支完成代码编写与自测。
   - **审核：** 发起 `Pull Request (PR)`申请合并至 `dev`，由其他成员进行 Code Review。
   - **发布：** `dev` 测试稳定后，择机合并至 `main`。
4. **提交规范：** 采用语义化提交信息，如 `feat:` (新功能)、`fix:` (修 Bug)；关键交付点打上 *Tag* 标签进行版本封存。

  ## 三、技术路线

  ### 1. 总体架构

  ​	本系统采用前后端分离架构设计，整体划分为前端展示层、后端业务逻辑层、数据持久层三层结构，层次清晰、耦合度低，便于分组开发与后期维护。

  1. 前端展示层

     ​	面向用户实现全部页面与交互，包含登录注册、目录树导航、文档编辑、版本查看、权限配置等界面；通过浏览器发起网络请求，接收后端接口数据并完成页面渲染与用户交互。

  2. 后端业务层

     ​	提供统一接口服务，负责接收前端请求，完成用户认证、权限校验、目录管理、文档操作、版本管理等核心业务逻辑处理，实现数据的加工与转发。

  3. 数据持久层

     ​	基于MySQL 数据库，使用标准SQL 语句完成数据的增、删、改、查操作，持久化存储用户信息、目录数据、文档内容、历史版本及权限配置等数据，保障数据长期稳定保存。前后端通过接口进行数据交互，各层级职责明确，能够适配小组多人分工并行开发，满足本次课程设计项目开发需求。

  ### 3.数据设计初步考虑

  #### 一、 主要实体或对象

  结合协同文档管理业务，系统抽取的五个核心实体对象如下：

  - **用户实体：** 记录系统使用者信息（含管理员与普通用户），用于登录认证、身份区分和权限绑定。
  - **目录实体：** 以多级文件夹形式存在，用于分类收纳文档，维护上下级目录的层级关系。
  - **文档实体：** 系统核心业务对象，包含文档标题、正文内容、所属目录、创建人等基础信息。
  - **文档版本实体：** 记录文档每次修改后的历史内容、版本编号与修改时间，用于版本查询与回溯。
  - **权限实体：** 绑定用户与对应的目录或文档，区分只读、编辑等操作权限，实现资源访问控制。

  

  #### 二、 关键数据表及数据关系

  系统采用 **MySQL** 数据库，通过以下五张核心数据表实现数据的持久化与关联：

  | **数据表名**         | **对应实体** | **说明**                                                     |
  | -------------------- | ------------ | ------------------------------------------------------------ |
  | **user**             | 用户表       | 存储注册用户基础信息，是权限与资源归属的核心关联主体。       |
  | **directory**        | 目录表       | 记录名称、父目录 ID 及创建者；通过自关联实现多级树状结构，与用户为多对一关系。 |
  | **document**         | 文档表       | 存储标题、正文、所属目录及创建人；与目录为多对一关系（一个目录下可有多个文档）。 |
  | **document_version** | 文档版本表   | 存储历史修改记录；通过文档 ID 与文档表形成一对多关联，记录多个历史镜像。 |
  | **permission**       | 权限表       | 关联中间表，建立用户与资源（目录/文档）的映射，通过权限字段控制操作范围。 |

  #### 三、 整体数据关系总结

  系统的数据架构逻辑清晰，依赖关系简单，便于使用 SQL 语句进行高效维护：

  1. **用户中心化：** 用户统一管理其名下的目录与文档。
  2. **层级分类：** 目录承载文档分类，支持无限级嵌套。
  3. **追踪溯源：** 文档关联多条版本记录，支持随时回滚。
  4. **灵活授权：** 权限表独立解耦，可精细化绑定用户与特定资源的访问关系。

  这种设计能够有效满足业务数据的持久化需求，并为后续的功能扩展预留了空间。

  ### 2. Git 协作方式

  本项目采用 **Git** 进行版本控制，确保团队开发的高效性与代码安全性：

  1. **仓库管理：** 建立远程托管仓库，作为唯一的代码与文档事实来源，成员定期执行 `pull/push` 保证版本同步。
  2. **分支管理策略：**
     - `main` 分支：长期维护的稳定分支，仅存放最终发布的正式版本。
     - `dev`分支：开发主分支，用于整合各模块成果并进行集成测试。
     - `feature/` 分支：功能分支（如 `feature/login`），成员在各自独立的分支开发，严禁直接修改 `main`。
  3. **提交与合并流程：**
     - **开发：** 在功能分支完成代码编写与自测。
     - **审核：** 发起 `Pull Request (PR)`申请合并至 `dev`，由其他成员进行 Code Review。
     - **发布：** `dev` 测试稳定后，择机合并至 `main`。
  4. **提交规范：** 采用语义化提交信息，如 `feat:` (新功能)、`fix:` (修 Bug)；关键交付点打上 *Tag* 标签进行版本封存。
